# Scheduler Parallel Coding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Development Scheduler 在 auto 审批模式下把同批无依赖任务分发给多个隔离的 Coding Worker，并将任务提交确定性地集成回 Run 分支。

**Architecture:** Scheduler 使用 LangGraph `Send` 动态 fan-out；每个 Worker 在任务级 Git worktree 中调用现有 Coding SubGraph，只向父图追加结构化任务结果。Integration barrier 按拓扑顺序 cherry-pick 成功提交、集中更新共享状态，再返回 Scheduler；interactive 模式在多审批能力完成前保持串行。

**Tech Stack:** Python 3.11+、LangGraph 1.2、FastAPI、Pydantic v2、asyncio、Git worktree、pytest

**Spec:** `docs/2026-10-21-Scheduler并行Coding/设计方案.md`

## Global Constraints

- Windows PowerShell 命令分隔使用 `;`，Python 命令使用仓库根 `.venv\Scripts\python.exe`。
- 现有串行流程必须保持兼容；`parallel_coding_enabled=false` 或 interactive 模式默认一次只调度一个任务。
- 并行 Worker 禁止写共享 Run 工作区，所有写操作发生在任务 worktree。
- 所有动态分支只合并 `coding_results`，不得并行覆盖 `task_dag`、`scratch`、`validation` 或 `changed_files`。
- Scheduler、reducer 和 Integration 必须能承受 LangGraph 节点 replay，不得重复创建副作用或重复 cherry-pick。
- 所有挂起载荷继续携带唯一 `approval_id`；本阶段不开放 interactive 多 Worker 并行。
- 任务 worktree 路径必须位于 `settings.workspaces_dir`，并锚定 Run worktree 所属仓库。
- 不自动 push，不触碰用户原始仓库工作区。

## Review Focus

- 同一批次节点 replay 时，任务结果和 Git 提交不会重复应用；Task 1 reducer 测试和 Task 4 integration 测试覆盖。
- 一个 Worker 失败时，其他独立 Worker 仍完成且失败依赖正确阻塞；Task 4 流程测试覆盖。
- 两个 Worker 修改同一文件时不会静默覆盖；Task 2 cherry-pick 冲突测试覆盖。
- interactive 模式和关闭并行开关时不会意外并行；Task 3 批次选择测试和 Task 4 图测试覆盖。
- 任务 worktree 创建中断后重试不会破坏已有工作区；Task 2 幂等创建测试覆盖。
